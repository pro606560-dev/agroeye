# Task 09 — เผยแพร่บน GitHub Pages — CHECKPOINT A [ใช้ reviewer]

## เป้าหมาย
ผู้ใช้เปิดแอปบนมือถือผ่านลิงก์ https ได้ และตรวจช่วง 1 ทั้งหมด

## ต้องทำเสร็จก่อน
08

## ขั้นตอน
1. ตรวจเกณฑ์ผ่านของ task 01–08 ซ้ำอีกรอบ แล้วรัน `design:accessibility-review` (ถ้ามี) กับหน้าแรก หน้ากรอกข้อมูล และหน้าผลลัพธ์ แก้ปัญหาระดับร้ายแรงก่อน
2. บอกผู้ใช้ทีละขั้นว่าต้องสร้าง repo บน GitHub ชื่อ `agroeye` (Public) และล็อกอิน git บนคอม (Git Credential Manager จะเปิดหน้าล็อกอินให้) **ห้ามขอรหัสผ่านหรือ token ในแชต**
3. เพิ่ม remote แล้ว push branch `main`
4. บอกผู้ใช้ทีละขั้นว่าเปิด GitHub Pages อย่างไร (Settings → Pages → Deploy from branch → main / root) แล้วรอลิงก์
5. เปิดลิงก์ตรวจเองก่อนว่าโหลดได้ (path ของไฟล์ต้องเป็นแบบ relative เพราะแอปจะอยู่ใต้ `/agroeye/`)
6. อัปเดต PROGRESS.md แล้วหยุด

## Skill ที่ใช้
- `design:accessibility-review`: ตรวจหน้าแรก หน้ากรอกข้อมูล หน้าผลลัพธ์ หน้ารายละเอียดพืช ก่อนส่งให้ผู้ใช้ทดสอบ
- `design:design-critique`: ถ่ายภาพหน้าจอขนาดมือถือแล้วให้ติ แก้ข้อที่สำคัญก่อนถึง CHECKPOINT

ถ้าไม่มี skill นี้ในรายชื่อ ให้ทำงานต่อตามหลักใน `docs/SPEC.md` แล้วจดใน PROGRESS.md ว่าไม่ได้ใช้

## รายการให้ผู้ใช้ทดสอบบน OPPO (ส่งให้ผู้ใช้ตามนี้)
1. เปิดลิงก์ใน Chrome แล้วเห็นหน้าแรก
2. กด "ตรวจแปลงใหม่" กรอกจนจบ เลือก ดินเหนียว, pH 5.5, น้ำขังนาน
3. เห็นพืช 3 อันดับพร้อมเหตุผล
4. กดดูรายละเอียดพืชอันดับ 1 ได้
5. ตัวอักษรอ่านได้สบายตาโดยไม่ต้องซูม
6. ปุ่มย้อนกลับของมือถือใช้ได้ทุกหน้า
7. ลองให้ผู้ใหญ่ที่บ้าน 1 คนใช้ แล้วจดว่าติดตรงไหน
