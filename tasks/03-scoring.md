## ขั้นตอน
1. `js/config.js`: ใส่น้ำหนักเริ่มต้นตาม SPEC เป็น object เดียว พร้อมคอมเมนต์ภาษาไทยว่าแต่ละค่าหมายถึงอะไร
2. `js/scoring.js`:
   - `scoreRange(value, optimal, tolerable)` คืนค่า 1 / 0.5 / 0 หรือ null (ถ้าไม่มีข้อมูล) และรองรับขอบที่เป็น null
   - `scoreTexture`, `scoreDrainage`, `scoreMonth` (ห่าง 1 เดือนข้ามปีได้ เช่น ธ.ค. กับ ม.ค.), `scoreLight`
   - `scoreCrop(plot, crop, climate)` คืน `{ cropId, score, coverage, confidence, factors: [{ key, plotValue, cropRange, factorScore, weight, used }] }`
   - `rankCrops(plot, crops, climate)` คืน `{ top: [3 อันดับ], others: [...], notEnoughData: [...] }`
3. ใส่คอมเมนต์ภาษาไทยอธิบายสูตรทีละบรรทัดในส่วน `scoreCrop` (ผู้ใช้จะคัดลอกไปใส่รายงาน)
4. `js/reasons.js`: แปลง `factors` เป็นเหตุผลภาษาไทยสั้น ๆ ตาม SPEC 4.3 ใช้คำง่าย
5. `tests/scoring.test.js` อย่างน้อย 15 ข้อ ครอบคลุม:
   - ค่าอยู่ในช่วงเหมาะ / ช่วงที่ทนได้ / นอกช่วง / อยู่บนขอบพอดี
   - ช่วงที่มีขอบเป็น null
   - ปัจจัยที่ไม่มีข้อมูลต้องถูกตัดออก ไม่นับเป็น 0
   - เดือนข้ามปี
   - คะแนนเท่ากันแล้วเรียงตาม coverage
   - พืชที่มีปัจจัยใช้ได้น้อยกว่า 2 ตัวต้องไปอยู่ใน notEnoughData
   - กรณีใน `data/test-scenarios.json` ทั้ง 5 กรณีต้องรันได้ (ยังไม่ต้องเช็กว่าได้พืชอะไร)
6. **ข้อสอบเฉลยของผู้ใช้:** ให้ `tests.html` อ่าน `tests/expected.json` แล้วคำนวณทุกข้อใน `scoreCases` ด้วยค่าใน `settings` (เดือน 5, ไม่มีข้อมูลอากาศ) เทียบกับ `expectedScore` (ยอมให้ต่างได้ ±1 จากการปัดเศษ) แสดงตัวใหญ่ว่า "ข้อสอบเฉลย ผ่าน X / Y" ข้อที่เป็น null (ถ้ามีในอนาคต) ให้แสดงสีเทาว่า "รอผู้ใช้กรอก" และตรวจ `ruleCases` ด้วย **ห้ามแก้ expected.json** ถ้าไม่ตรง ให้แก้โค้ด ถ้าเชื่อว่าคำตอบของผู้ใช้ผิด ให้อธิบายวิธีคิดให้ผู้ใช้ดูทีละขั้น แล้วให้ผู้ใช้ตัดสิน
7. เพิ่มส่วนใน `tests.html` ที่รันทั้ง 5 กรณีแล้วแสดงตาราง: กรณี × พืช 3 อันดับ + คะแนน
