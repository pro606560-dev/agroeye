# สเปกแอป AgroEye

## 1. ภาพรวม
- **ชื่อ:** AgroEye — AI ผู้ช่วยวิเคราะห์พื้นที่เชิงลึกสำหรับปลูกพืชท้องถิ่น
- **ปัญหา:** เกษตรกรไม่รู้ว่าแปลงของตัวเองควรปลูกพืชอะไร และควรดูแลอย่างไร
- **ผู้ใช้หลัก:** เกษตรกรสูงอายุในอำเภอแม่ทะ จังหวัดลำปาง (พิกัดอำเภอ 18.135, 99.513)
- **ผู้ประเมิน:** ครูวิชา IS (I30201) กำหนดส่ง 8 เม.ย. 2570
- **สิ่งที่แอปทำ:** ผู้ใช้กรอกข้อมูลแปลง แล้วแอปแนะนำพืช 3 อันดับพร้อมเหตุผล วิธีดูแล ความเสี่ยง และเดือนที่ควรปลูก
- **สมมติฐานที่แอปต้องช่วยพิสูจน์**
  1. ถ้าสภาพแวดล้อมของแต่ละพื้นที่ต่างกัน แอปจะแนะนำพืชต่างกัน
  2. แอปประมวลผลได้ในเวลาไม่นาน

## 2. ขอบเขต
**ต้องมี:** กรอกข้อมูลแปลง, ใช้ได้แม้ไม่มีเน็ต, แนะนำ 3 อันดับพร้อมเหตุผล, หน้ารายละเอียดพืช, ประวัติแปลง, ปฏิทินปลูก, หน้าพิสูจน์สมมติฐานพร้อมกราฟ, ดึงสภาพอากาศ, อ่านออกเสียงภาษาไทย, AI (Gemini) ช่วยอธิบาย

**ส่วนเสริม (ทำเมื่อผู้ใช้ขอเท่านั้น):** รับค่าจากเซนเซอร์ ESP32

**ไม่ทำ:** อำเภออื่น, ระบบสมาชิก/ล็อกอิน, เซิร์ฟเวอร์หรือฐานข้อมูลออนไลน์, ทำนายราคาหรือผลผลิต, ตรวจโรคพืชจากรูป

## 4. วิธีคำนวณคะแนน (`js/scoring.js`)
AI ภายนอก **ไม่ได้เป็นคนเลือกพืช** แอปเลือกด้วยสูตรนี้ จึงทำงานได้แม้ไม่มีเน็ต และอธิบายในรายงานได้ทุกขั้น

### 4.1 คะแนนแต่ละปัจจัย (0, 0.5 หรือ 1)
| ปัจจัย | ค่าจากแปลง | เทียบกับ crops.json | วิธีให้คะแนน |
| --- | --- | --- | --- |
| pH | ตัวเลขที่ผู้ใช้กรอก | `ph.optimal` / `ph.tolerable` | อยู่ในช่วงเหมาะ = 1, อยู่ในช่วงที่ทนได้ = 0.5, นอกช่วง = 0 |
| ประเภทดิน | heavy / medium / light | `texture.good` / `texture.ok` | อยู่ใน good = 1, อยู่ใน ok = 0.5, ไม่อยู่ในทั้งสอง = 0 |
| การระบายน้ำ | น้ำขัง (poor) / ไม่ขัง (good) | `drainage.value` | ถ้าพืชต้องการ good แต่แปลงน้ำขัง = 0, กรณีอื่น = 1 |
| เดือนที่จะปลูก | เลข 1–12 | `plantingMonths.months` | อยู่ในรายการ = 1, ห่าง 1 เดือน = 0.5, ห่างกว่านั้น = 0 |
| อุณหภูมิ | พืชล้มลุก (`lifeForm` = annual): ค่าเฉลี่ยของเดือนที่อยู่ในแปลง / ไม้ยืนต้น (perennial): ค่าเฉลี่ยทั้งปีของพื้นที่ (ดูช่อง `tempBasis`) | `tempC` | ใช้แบบเดียวกับ pH แล้วลดคะแนนด้วยตัวกรองความหนาว (ข้อ 4.1.1) |
| ฝน | ฝนรวมต่อปีของแม่ทะ | `rainMmYear` | ใช้แบบเดียวกับ pH (ขอบบนที่เป็น null = ไม่จำกัด) |
| แสง | แดดจัด / ร่มรำไร (ถ้าผู้ใช้ตอบ) | `light.value` | ถ้าพืชต้องการ full-sun แต่แปลงร่ม = 0, กรณีอื่น = 1 |
| ความชื้นดิน, N/P/K | ค่าที่ผู้ใช้กรอก | ยังไม่มีข้อมูลใน crops.json | ยังไม่ใช้คำนวณ แต่เก็บค่าไว้ในประวัติ |

ถ้าช่วง optimal เป็น null แต่ tolerable มีค่า ให้นับว่าอยู่ในช่วงที่ทนได้ = 0.5 และนอกช่วง = 0

#### 4.1.1 อุณหภูมิของไม้ยืนต้นและตัวกรองความหนาว (ทำใน task 10)
- ค่าอุณหภูมิของ ECOCROP เป็นช่วงของอุณหภูมิเฉลี่ยตลอดฤดูเติบโต และมีอุณหภูมิที่ทำให้ตายแยกต่างหาก (FAO-ITC-ECOCROP, CDKN-CIRCA-WP21) ไม้ยืนต้นอยู่ในแปลงทั้งปี จึงเทียบกับอุณหภูมิเฉลี่ยรายปี ไม่ใช่เดือนที่ปลูก
- ตัวกรองความหนาว: ถ้าพืชมี `coldLimitC` และอุณหภูมิต่ำสุดเฉลี่ยของเดือนที่หนาวที่สุดของพื้นที่ต่ำกว่าช่วงนั้น ให้**ลด**คะแนนปัจจัยอุณหภูมิ ห้ามตัดเป็น 0 พืชที่ไม่มี `coldLimitC` ไม่ต้องกรอง
- ใช้สถิติภูมิอากาศสถานีลำปาง (TMD-LAMPANG-9120) แทนแม่ทะ และบอกผู้ใช้ในแอป
- ข้าวไวแสง (`photoperiodSensitive`) มี `cycleDays` เป็น null และใช้ `harvestApprox` (วันที่เก็บเกี่ยว) แทน

### 4.2 คะแนนรวม
```
score = 100 × Σ(น้ำหนัก × คะแนนปัจจัย) ÷ Σ(น้ำหนัก)
```
- **นับเฉพาะปัจจัยที่มีค่าทั้งฝั่งแปลงและฝั่งพืช** ถ้าฝั่งใดฝั่งหนึ่งเป็น null ให้ตัดปัจจัยนั้นออกจากทั้งตัวตั้งและตัวหาร ไม่นับเป็น 0
- น้ำหนักเริ่มต้นใน `js/config.js`: pH = 3, ประเภทดิน = 3, การระบายน้ำ = 2, เดือนที่จะปลูก = 2, อุณหภูมิ = 2, ฝน = 2, แสง = 1
- **ความครอบคลุมของข้อมูล** = Σ น้ำหนักของปัจจัยที่ใช้ได้ ÷ Σ น้ำหนักทั้งหมด แปลงเป็นความมั่นใจ: ≥ 70% = สูง, 40–69% = ปานกลาง, < 40% = ต่ำ
- พืชที่ใช้ปัจจัยได้น้อยกว่า 2 ตัว ให้ซ่อนจากอันดับ และแสดงในรายการ "ข้อมูลไม่พอจะแนะนำ"
- ถ้าคะแนนเท่ากัน ให้พืชที่ความครอบคลุมสูงกว่าอยู่ก่อน
- ผลที่คืนมาต้องมีคะแนนแยกทุกปัจจัย เพื่อใช้สร้างเหตุผล ทำตาราง และทำกราฟ

### 4.3 เหตุผลภาษาไทย
สร้างจากคะแนนแยกปัจจัย ตัวอย่าง:
- "ดินร่วน เหมาะกับถั่วลิสง"
- "ดินเปรี้ยวไปนิด (pH 5.2) แต่พืชนี้ทนได้"
- "เดือนนี้ไม่ใช่ช่วงปลูก ควรรอถึง พ.ค."

ถ้าพืชมีความเสี่ยงที่ตรงกับแปลง (เช่น ดินเปรี้ยวมาก) ให้แสดงด้วย

คำเรียก pH (แสดงคำอย่างเดียว ไม่มีผลกับคะแนน): ≤ 5.5 "ดินเปรี้ยวมาก", 5.6–6.5 "ดินเปรี้ยว", 6.6–7.3 "ปกติ" (ตามกรมพัฒนาที่ดินและ USDA NRCS), > 7.3 "ดินเป็นด่าง" ห้ามใช้คำว่า "ดินเปรี้ยวจัด" กับค่า pH อย่างเดียว เพราะกรมพัฒนาที่ดินหมายถึงดินกรดกำมะถัน

## 7. หลักออกแบบสำหรับผู้สูงอายุ
- ตัวอักษรเนื้อหาไม่ต่ำกว่า 18px, หัวข้อไม่ต่ำกว่า 24px, ปุ่มสูงไม่ต่ำกว่า 56px, ระยะระหว่างปุ่มไม่ต่ำกว่า 12px
- สีตัวอักษรกับพื้นต้องตัดกันชัด (ผ่าน WCAG AA)
- หน้าละ 1 คำถาม ทุกตัวเลือกมีรูปหรือไอคอนประกอบ
- ไม่ใช้ศัพท์เทคนิค เช่น ใช้ "ดินเปรี้ยว" แทน "pH ต่ำ" และ "ดินเป็นด่าง" แทน "pH สูง" (แสดงตัวเลขเล็ก ๆ ข้างคำได้)
- ปุ่ม "ย้อนกลับ" อยู่ตำแหน่งเดิมทุกหน้า
- ข้อความแจ้งผิดพลาดต้องบอกว่าเกิดอะไรขึ้นและต้องทำอะไรต่อ
- รองรับจอมือถือกว้าง 360px เป็นหลัก
- ฟอนต์: ใช้ฟอนต์ไทยของระบบ หรือเก็บไฟล์ฟอนต์ (ใบอนุญาต OFL) ไว้ใน `lib/fonts/` ห้ามโหลดจาก Google Fonts ตอนแอปทำงาน
